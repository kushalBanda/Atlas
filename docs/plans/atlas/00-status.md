- Scope: backend only for v1. No UI screens. Frontend is future work, not decided yet.
- Source specs: `docs/superpowers/specs/2026-08-25-hld-system-design.md` (wins on conflict), `docs/superpowers/specs/2026-08-24-folder-structure-design.md` (layout still holds), `docs/superpowers/specs/2026-08-24-language-choice-design.md` (stack: Go + TS + OTel, background).
- Locked decisions from HLD: DuckDB embedded storage (ClickHouse behind interface, not built), OTel Collector receivers reused (no custom collectors), auto-discovery build order process-scan → Docker → K8s, in-process plugin registry (`pkg/plugin`), unified span model (infra + LLM/agent), rule-based root-cause scoring at trace-close time (self-time threshold default 30%, unvalidated).
- Open items flagged in handoff doc, not yet resolved: trace-close timeout default value, discovery config file format.
- Backtrack 2026-08-26: idle-timeout as the *primary* trace-close trigger was wrong — a long-running child span (e.g. an LLM call) could close the trace before it ever arrived. Fixed: primary trigger is root-span arrival (parent_span_id IS NULL), idle-timeout (30s) is fallback-only for the crashed-hop case. Validated against Phoenix (root-span-as-schema) and Langfuse (no idle-wait, per-observation retry/backoff). See `02-architecture.md` Flow and `03-program-design.md` Store interface / Watcher / Least confident decisions #2.
- API prefix 2026-08-26: dropped `/v1/` from Atlas's own API (`/traces`, `/traces?filter=`, `/logs`, `/metrics`, `/discovery/targets`, `/healthz`). Kept `POST /v1/traces` for OTLP ingest — that's the OTLP/HTTP protocol's own fixed default path, not Atlas's API versioning; renaming it would break standard OTel exporters.
- See `future.md`: trace-view flexibility (waterfall now, query API stays view-agnostic so flame graph/service map/etc. can be added later without a data-model change) and root-cause scorer deep-dive (defer refining the heuristic/threshold until base structure is running with real trace data).
